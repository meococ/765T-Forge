# Deploy — reliability wave (branch `forge-reliability-20261029`)

What ships: synchronous `forge_exec_lisp`, no-viewer + fill-the-sheet `forge_plot_to_pdf`, `.lsp`
support + readable stdout in `forge_run_script`, block-aware `forge_linework_*` / `forge_entity_list`
(`includeBlocks`), new `forge_text_list`, new `forge_doc_activate`, and `forge_view_capture window`.
Server and plugin change together. Deploy both or neither: the new server talking to the old
plugin answers `unknown tool` for the new tools and keeps the old exec_lisp/plot behaviour.

Verified before deploy, with no live AutoCAD: `dotnet build/test .\765T-Forge.ServerOnly.slnf -c Release`
passes (376/376 tests), and the 2025 plugin builds cleanly to `artifacts\staging-20261029\Forge.Plugin\2025`
(Release, 0 errors, 0 CS warnings). Everything that touches the AutoCAD API still needs the live
smoke test in section 7.

## 1. Stop, in this order

1. **Let the live agent finish.** The client-job agent must finish its current step and save its
   drawings (`forge_doc_save`). No tool call may be in flight: no plot, publish, batch or `run_script`
   still running.
2. **Stop the MCP server.** Close every MCP client session that has `765t-forge` loaded (Claude
   Code / T3 / Paseo threads). `Forge.Server.exe` is a stdio child of the client and exits with
   the session. Do this before closing AutoCAD, so that no agent call can land while AutoCAD is
   shutting down. Such a call would end in a `plugin_request_timeout` and need the read-back
   recovery steps.
   ```powershell
   Get-Process Forge.Server -ErrorAction SilentlyContinue   # must print nothing
   ```
3. **Close AutoCAD 2025** normally (File > Exit) and answer any save prompts yourself.
   ```powershell
   Get-Process acad, accoreconsole -ErrorAction SilentlyContinue   # must print nothing
   ```

Both processes must be down before any file is replaced. The server holds `bin\Debug\net8.0\*.dll`
open, and AutoCAD holds `Forge.Plugin.dll` and `Forge.Shared.dll` inside the bundle.

## 5. Plugin: copy the staged build into the bundle

1. Open `%APPDATA%\Autodesk\ApplicationPlugins\765T-Forge.bundle\PackageContents.xml` and read
   `ModuleName`. The repo layout is `./Contents/Windows/Forge.Plugin.dll`; a 2025 bundle should
   declare `SeriesMin="R25.0"`. Copy into whatever folder `ModuleName` points to.
2. Copy **every** staged file. `Forge.Shared.dll` is mandatory: the plugin uses new Shared types
   (`LispEval`, `Pc3File`, `PlotLayoutMath`, `BlockWalk`, `TextRead`, `DocumentMatcher`). If only
   `Forge.Plugin.dll` is copied, the plugin fails at load or on first use with a `TypeLoadException` or
   `MissingMethodException`.
   ```powershell
   $dst = "$env:APPDATA\Autodesk\ApplicationPlugins\765T-Forge.bundle\Contents\Windows"   # = ModuleName folder
   Copy-Item D:\765T-Forge\artifacts\staging-20261029\Forge.Plugin\2025\* $dst -Force
   foreach ($f in 'Forge.Plugin.dll','Forge.Shared.dll') {
     (Get-FileHash "D:\765T-Forge\artifacts\staging-20261029\Forge.Plugin\2025\$f").Hash -eq (Get-FileHash "$dst\$f").Hash
   }   # both True
   ```
   The plugin carries the `ForgeTargetYear=2025` stamp, so AutoCAD 2025 loads it without
   `HOST_YEAR_MISMATCH`.

## 6. Restart, in this order

1. Start AutoCAD 2025 and open any drawing. On the Start tab only health, version and
   `forge_doc_list_open` answer. Run `MCP_STATUS` and check that the pipe name matches
   `FORGE_PIPE_NAME`.
2. Start a **new** MCP client session. The tool list is cached per session, so only a new session
   lists `forge_doc_activate` and `forge_text_list`.
3. Run `forge_system_health`. Expect `ok=true`, the pipe connected and the plugin answering.
4. Hand the client-job drawings back to the live agent **only after** section 7 passes. Run every
   smoke step on scratch drawings, never on the client's files.

### 7.1 `forge_exec_lisp` — the value comes back synchronously
This tool needs `FORGE_ENABLE_UNSAFE_OPS=true` in the server env and `unsafeAcknowledged=true` on
every call. Without them the expected answer is `unsafe_not_acknowledged`; record that and skip the
rest of 7.1.

| Call (`lisp=`) | Expected |
|---|---|
| `(+ 1 2)` | `ok=true`, `data.mode="sync_eval"`, `queued=false`, `completed=true`, `result=3`, `resultText="3"`, `resultType="int"`, `envelope=true` |
| `(list (getvar "DWGNAME") 1.5 '(1 . "a"))` | `resultType="list"`, `resultText="(\"nested.dwg\" 1.5 (1 . \"a\"))"` |
| `(/ 1 0)` | `ok=false`, `error.code="lisp_error"`, message contains `divide by zero`, `data.completed=true` |
| `(+ 1 2` | `ok=false`, `error.code="lisp_unbalanced"`; nothing evaluated |
| `(+ 1 2)` with `dryRun=true` | dry-run plan with `normalized="(+ 1 2)"` |

Failure signal: `mode="queued_fallback"` means the `acedEvaluateLisp` export did not bind in this
AutoCAD build; `fallbackReason` says why. `lisp_eval_failed` with a status means the evaluator
refused the call in this context. Report either one; do not work around it.
